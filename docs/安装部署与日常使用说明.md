# xxsj-fs-ob 安装部署与日常使用说明

> 适用于第一次接触本项目的用户。  
> 本文将“首次安装部署”和“日常使用”分开说明，并明确 Codex、Skill、Worker、飞书机器人和飞书多维表格各自承担的角色。

---

## 1. 这个项目是什么

`xxsj-fs-ob` 是一套运行在用户自己电脑上的信息收集系统，同时提供 Codex Skill 集成。

当前正式实现的用途是：

1. 用户把抖音链接发送给自己的飞书机器人；
2. 飞书机器人把链接写入飞书多维表格；
3. 本地 Worker 自动领取任务；
4. 下载视频并完成语音转写；
5. 使用 AI 生成摘要、分类和值得保存的信息；
6. 生成 Markdown；
7. 写入用户自己的 Obsidian；
8. 将处理状态和结果路径回写飞书多维表格。

这里所说的 **Base，就是飞书多维表格**。

### 1.1 它既是项目，也是 Codex Skill

项目主体负责真正的业务处理：

- 飞书多维表格任务队列；
- Worker；
- 抖音解析与下载；
- Qwen-ASR；
- Faster-Whisper Large-v3 备用转写；
- DeepSeek 摘要与分类；
- Obsidian 写入；
- 去重、断点恢复、幂等和失败处理。

`SKILL.md` 是给 Codex 读取的操作说明。它告诉 Codex：

- 这个项目做什么；
- 哪些请求应该调用它；
- 如何安装；
- 如何检查环境；
- 如何启动和停止 Worker；
- 如何排查故障。

因此：

- Codex 可以帮助安装、启动和维护；
- Codex 不是项目的运行依赖；
- Worker 才是日常自动处理任务的后台进程。

## 2. 当前支持范围

### 已正式实现

- 抖音视频链接；
- Windows 本地运行；
- 飞书机器人；
- 飞书多维表格；
- Qwen-ASR；
- Faster-Whisper Large-v3 fallback；
- DeepSeek 内容分析；
- Obsidian Markdown 归档。

### 尚未正式实现

- 公众号；
- B站；
- YouTube；
- 推特 / X；
- 小红书。

目录中出现这些平台名称，只表示预留扩展位置，不代表处理链已经可用。

例如：把一条 B站链接写入飞书多维表格，不代表当前 Worker 已经能处理它。

# 第一部分：首次安装部署

首次安装只需要做一次。安装完成后，日常使用不需要反复创建飞书应用、重新安装依赖或重新填写 API Key。

## 3. 首次安装前需要准备什么

### 3.1 Windows 电脑

电脑负责运行 Worker，并需要访问：

- 飞书；
- 抖音页面及媒体；
- Qwen 服务；
- DeepSeek 服务。

Worker 运行期间电脑需要保持开机，并避免进入会完全停止网络和后台进程的休眠状态。

### 3.2 Codex：可选但推荐

Codex 可以帮助：

- 下载或复制项目；
- 检查环境；
- 安装依赖；
- 创建本地配置；
- 验证 `SKILL.md`；
- 运行 `install.ps1`；
- 运行 `doctor.ps1`；
- 启动和停止 Worker；
- 排查错误。

不使用 Codex，也可以按照说明手动部署。

### 3.3 自己的飞书应用和机器人

每个使用者都应创建自己的飞书自建应用，并启用机器人能力。

用户需要完成：

1. 创建飞书自建应用；
2. 启用机器人；
3. 配置飞书多维表格读写权限；
4. 发布应用版本；
5. 将应用加入目标多维表格并授予权限；
6. 在本机安全配置中填写自己的 App ID 和 App Secret。

不要在聊天、截图、Issue、日志或 GitHub 中公开 App Secret。

### 3.4 自己的飞书多维表格

飞书多维表格承担：

- 任务队列；
- 状态面板；
- 原始链接登记；
- 结果路径登记；
- 错误记录。

常见状态：

```text
pending → processing → draft_ready → done
```

失败时可能进入：

```text
failed
```

字段应以仓库中的飞书 Base 配置说明为准，通常至少需要：

- 原始链接；
- 来源平台；
- 处理状态；
- 平台作品 ID；
- 知识库路径；
- 错误信息；
- 创建时间；
- 完成时间。

### 3.5 模型服务

当前版本需要：

- Qwen-ASR：主要语音转写；
- DeepSeek：摘要、分类和值得保存的信息；
- Faster-Whisper Large-v3：本地备用转写。

使用者需要自行准备模型账户和 API Key。

### 3.6 Obsidian

准备自己的 Obsidian Vault，并在配置中填写路径。

推荐目录：

```text
000-Inbox
└── 001-信息中心
    ├── 抖音
    ├── B站
    ├── 小红书
    ├── 推特
    ├── YouTube
    └── 公众号
```

当前只有“抖音”处理链正式可用。

### 3.7 本地依赖

项目可能使用：

- Node.js；
- Python；
- FFmpeg；
- 项目依赖包；
- Faster-Whisper；
- Large-v3 模型。

Codex 可以协助安装，但模型账户、管理员确认和部分系统级软件仍需要用户参与。

## 4. 安装为 Codex Skill

Codex Skill 是一个包含 `SKILL.md` 的目录，可同时包含脚本、文档和资源。

### 4.1 不要盲目硬编码安装目录

不同 Codex 客户端、版本或运行方式可能使用不同的用户级 Skill 位置。

常见位置包括：

```text
%USERPROFILE%\.codex\skills\xxsj-fs-ob
%USERPROFILE%\.agents\skills\xxsj-fs-ob
```

正确原则是：

1. 找到当前 Codex 中已经能正常显示的一个 Skill；
2. 检查它的真实目录；
3. 将 `xxsj-fs-ob` 安装到同一层级；
4. 两个候选目录中只保留一份同名 Skill；
5. 目录存在不等于安装成功；
6. 必须以 Codex Skill 选择器实际出现为最终验收。

在本项目作者当前使用的 Codex 客户端中，实测有效目录是：

```text
%USERPROFILE%\.codex\skills\xxsj-fs-ob
```

其他用户仍应以自己的客户端实际发现路径为准。

### 4.2 `SKILL.md` 必须具备元数据

`SKILL.md` 必须从文件第一个字符开始包含 YAML front matter：

```yaml
---
name: xxsj-fs-ob
description: 通过飞书多维表格任务队列启动和维护本地信息收集 Worker，将抖音视频转写、分析并归档到 Obsidian。
---
```

要求：

- `---` 前没有空行；
- `---` 前没有 BOM；
- `name` 为 `xxsj-fs-ob`；
- `description` 非空；
- 文件名确实是 `SKILL.md`。

缺少这些内容时，文件即使已经复制到目录，Codex 也可能无法发现它。

### 4.3 让 Codex 帮助安装

将仓库或 Release ZIP 交给 Codex，并发送：

```text
请安装 xxsj-fs-ob。

先阅读 SKILL.md、README 和 docs 下的部署说明，然后：

1. 找到当前 Codex 实际使用的用户级 Skill 目录；
2. 以一个已经能在 Skill 选择器中正常显示的 Skill 作为参照；
3. 只安装一份 xxsj-fs-ob；
4. 验证 SKILL.md 从第一个字节开始包含合法 YAML front matter；
5. 检查 Node、Python、FFmpeg 和项目依赖；
6. 创建本地配置，但不要要求我在聊天中发送 App Secret、API Key 或 Token；
7. 告诉我需要自行完成的飞书应用、机器人、Base 和模型账户步骤；
8. 运行 install.ps1 和 doctor.ps1；
9. 完全重启 Codex；
10. 在 Skill 选择器中确认 xxsj-fs-ob 实际出现；
11. 环境检查通过后暂停，不要擅自启动长期 Worker。
```

### 4.4 手动安装

将完整的 `xxsj-fs-ob` 文件夹复制到当前 Codex 实际使用的用户级 Skill 目录。

目录至少包含：

```text
xxsj-fs-ob
├── SKILL.md
├── README.md
├── start-xxsj-fs-ob-worker.cmd
├── start-xxsj-fs-ob-worker.ps1
├── scripts
├── config
├── docs
└── references
```

完成后：

1. 完全退出 Codex；
2. 重新启动；
3. 新建会话；
4. 打开 Skill 选择器；
5. 输入 `xx` 或 `xxsj` 过滤；
6. 确认出现 `xxsj-fs-ob`。

也可以通过 `$xxsj-fs-ob` 或当前客户端提供的 Skill 选择方式调用。

## 5. 首次配置

复制配置模板，生成自己的本地配置。

通常需要填写：

- 飞书应用 App ID；
- App Secret 的安全位置；
- lark-cli Profile；
- 飞书 Base 标识；
- 表格标识；
- Obsidian Vault 路径；
- Qwen 配置；
- DeepSeek 配置；
- Python、FFmpeg 和本地模型路径。

安全原则：

- 使用自己的配置；
- 不在 `.env.example` 中写真实密钥；
- 真实 `.env` 不提交 Git；
- 不把密钥放进 README、截图或 Issue；
- Windows 路径含空格时使用引号。

## 6. 首次安装与检查

先进入实际安装目录。

当前作者环境示例：

```powershell
cd "$HOME\.codex\skills\xxsj-fs-ob"
```

其他用户需替换成自己的实际安装目录。

运行安装：

```powershell
.\scripts\install.ps1
```

运行环境检查：

```powershell
.\scripts\doctor.ps1
```

Doctor 应检查：

- 配置完整性；
- `SKILL.md` front matter；
- 飞书 bot identity；
- Base 读取权限；
- Obsidian 路径；
- Node、Python 和 FFmpeg；
- 必要目录和依赖；
- 是否存在重复 Skill；
- 当前快捷方式目标是否一致。

只有 doctor 通过后，才进入日常使用。

---

## 7. 首次端到端验证

使用一条专用抖音测试记录：

1. 启动 Worker；
2. 给自己的飞书机器人发送可访问的抖音链接；
3. 确认多维表格新增任务；
4. 确认状态从 `pending` 进入处理状态；
5. 确认视频被下载和转写；
6. 确认 Obsidian 生成 Markdown；
7. 确认多维表格最终为 `done`；
8. 确认知识库路径正确；
9. 确认没有泄露 API Key 或签名媒体 URL。

首次验证通过后，安装部署结束。

# 第二部分：日常使用

日常使用不需要重新安装，也不需要每天打开 Codex。

基本流程：

```text
启动 Worker
→ 给飞书机器人发送抖音链接
→ 等待自动处理
→ 在 Obsidian 查看笔记
→ 不使用时停止 Worker
```

用户只需要保留两种启动方式。

## 8. 启动方式一：让 Codex 启动 Worker

在 Codex 中选择 `xxsj-fs-ob`，或者在提示词中提及 `$xxsj-fs-ob`，然后发送：

```text
请使用 xxsj-fs-ob 检查 Worker 状态。
如果环境正常且 Worker 尚未运行，请启动 Worker。
不要修改代码和配置。完成后告诉我 PID、日志路径和停止方式。
```

Codex 会调用 Skill 中已有的启动脚本。

Worker 启动后，Codex 可以关闭。Codex 不是后台运行依赖。

## 9. 启动方式二：双击快捷方式或 CMD

普通用户推荐双击：

```text
启动 xxsj-fs-ob Worker.lnk
```

也可以直接双击 Skill 根目录中的：

```text
start-xxsj-fs-ob-worker.cmd
```

调用链是：

```text
快捷方式
→ start-xxsj-fs-ob-worker.cmd
→ start-xxsj-fs-ob-worker.ps1
→ scripts\start-worker.ps1
→ Worker
```

其中：

- `.cmd` 是普通用户双击入口；
- `.ps1` 是底层技术脚本；
- 不把右键运行 `.ps1` 作为第三种普通用户启动方式；
- `.cmd` 使用自身目录定位 `.ps1`，因此不应写死用户名和安装盘符。

当前作者环境中的快捷方式位于：

```text
D:\下载\启动 xxsj-fs-ob Worker.lnk
```

其他用户可以在自己常用的位置创建快捷方式。

## 10. 发送链接触发任务

Worker 启动后，把抖音链接发送给自己的飞书机器人。

完整流程：

```text
飞书机器人收到链接
        ↓
飞书多维表格创建 pending 记录
        ↓
本地 Worker 查询并领取任务
        ↓
解析抖音内容和媒体地址
        ↓
下载视频
        ↓
Qwen-ASR 转写
        ↓
失败时切换 Faster-Whisper Large-v3
        ↓
DeepSeek 生成摘要、分类和值得保存的信息
        ↓
生成 Markdown
        ↓
原子写入 Obsidian
        ↓
飞书多维表格更新为 done
```

### Worker 没有运行

任务可能已经进入多维表格，但会停留在 `pending`。

重新启动 Worker 后，可继续领取积压任务。

### Codex 没有运行

不影响已经启动的 Worker。

### 电脑关机

无法处理新任务。重新开机后需要再次启动 Worker，除非另外配置 Windows 服务或计划任务。

## 11. 查看结果

### 飞书多维表格状态

| 状态 | 含义 |
|---|---|
| `pending` | 已进入队列，等待 Worker |
| `processing` | Worker 正在处理 |
| `draft_ready` | 内容已生成，处于提交阶段 |
| `done` | 已写入 Obsidian 并完成回写 |
| `failed` | 处理失败，需要查看错误信息 |

### Obsidian

抖音笔记写入用户配置的抖音目录。

文件名通常为：

```text
<笔记标题> - <完整平台作品ID>.md
```

内容通常包括：

- 标题；
- 作者；
- 平台；
- 发布时间；
- 原始链接；
- 内容提要；
- 完整逐字稿；
- 分类；
- 值得保存的信息；
- ASR 和处理说明。

---

## 12. 停止 Worker

可以让 Codex 停止，也可以在 Skill 目录执行：

```powershell
.\scripts\stop-worker.ps1
```

停止后：

- 飞书机器人仍可接收消息；
- Base 仍可保存任务；
- 新任务不会继续下载和处理；
- 下次启动 Worker 后可以继续处理队列。

---

## 13. 单次处理

只想处理一轮任务时，可以使用：

```powershell
.\scripts\run-once.ps1
```

部分版本支持指定飞书 Base 的真实 Record ID：

```powershell
.\scripts\run-once.ps1 -RecordIds "recxxxxxxxx"
```

这里需要的是飞书 Base Record ID，不是平台去重 ID。

当前版本只支持抖音。即使指定了一条 B站记录，也不能完成 B站下载和归档。

# 第三部分：常见问题

## 14. 为什么文件已复制，Codex 仍然看不到 Skill

优先检查：

1. 是否安装到当前客户端实际扫描的目录；
2. 是否同时存在两份同名 Skill；
3. `SKILL.md` 是否在 Skill 根目录；
4. 是否多嵌套了一层文件夹；
5. `SKILL.md` 是否以合法 YAML front matter 开头；
6. 是否存在 BOM 或隐藏字符；
7. `name` 是否为 `xxsj-fs-ob`；
8. Codex 是否已经完全重启；
9. `config.toml` 是否禁用了该 Skill。

最终判断标准不是“文件存在”，而是：

> 在 Codex Skill 选择器中实际出现 `xxsj-fs-ob`。

## 15. Codex 必须一直打开吗

不需要。

Codex 可以帮助启动 Worker，但 Worker 启动后是独立本地进程。

## 16. PowerShell 窗口必须一直开着吗

取决于原有 `start-worker.ps1` 的实现。

首次安装时应确认：

- Worker PID；
- 日志路径；
- 关闭启动窗口后 Worker 是否继续；
- `stop-worker.ps1` 是否有效。

## 17. 需要 Docker 吗

当前 Windows 本地版本不要求 Docker。

- `doctor.ps1`：环境检查；
- Worker：后台处理程序；
- Docker：可选容器部署方式，目前不是必需项。

## 18. 为什么任务一直是 pending

检查：

1. Worker 是否运行；
2. 飞书应用是否有 Base 权限；
3. Base 配置是否正确；
4. 网络是否正常；
5. `.env` 是否加载；
6. 是否存在锁或残留进程；
7. Worker 日志是否报错；
8. 来源平台是否受支持。

## 19. 为什么 B站任务不处理

当前正式版本只实现抖音平台适配器。

B站是后续规划，不应把 B站任务标记为成功。理想行为是明确显示不支持的平台，而不是进入抖音处理链。

## 20. 会不会重复生成笔记

项目包含：

- Record ID 去重；
- 平台作品 ID 去重；
- 状态幂等；
- Obsidian 冲突保护；
- 用户修改检测。

## 21. 中途失败会不会从头开始

项目会保存阶段状态：

- 视频已下载时不重复下载；
- ASR 已完成时不重复转写；
- DeepSeek 已完成时不重复分析；
- Obsidian 已写入但 Base 回写失败时只补写 Base。

# 第四部分：安全与公开发布

## 22. 不要提交到 GitHub 的内容

公开仓库不得包含：

- `.env`；
- App Secret；
- Qwen 或 DeepSeek API Key；
- Token、Cookie、Authorization；
- 个人飞书 App ID 和 Base 标识；
- 个人 Obsidian 绝对路径；
- 真实视频；
- 真实逐字稿和笔记；
- Worker 日志；
- 本地任务缓存；
- 带签名媒体 URL；
- 内部验收报告中的私人部署信息。

公开版本只保留：

- `.env.example`；
- 占位符；
- 合成测试数据；
- 通用安装说明；
- 无私人信息的脚本和模板。

## 23. API 和内容合规

使用者应遵守：

- 飞书平台规则；
- 抖音访问规则；
- 模型服务条款；
- 内容版权要求；
- 组织的数据和隐私政策。

不要使用本项目绕过付费、登录、权限控制或平台安全机制。

## 首次安装部署

```text
准备飞书应用和机器人
→ 创建飞书多维表格
→ 准备 Qwen / DeepSeek API
→ 准备 Obsidian
→ 确认 Codex 实际 Skill 目录
→ 安装 xxsj-fs-ob
→ 验证 SKILL.md front matter
→ 填写 .env
→ 运行 install.ps1
→ 运行 doctor.ps1
→ 在 Skill 选择器中确认出现
→ 做一次抖音端到端测试
```

## 日常使用

```text
方式一：让 Codex 启动 Worker
或
方式二：双击 CMD / 快捷方式启动 Worker
→ 给飞书机器人发送抖音链接
→ 等待处理
→ 在 Obsidian 查看笔记
→ 不使用时停止 Worker
```

最重要的运行条件：

> 飞书机器人正常 + 飞书多维表格正常 + 本地 Worker 正在运行。
