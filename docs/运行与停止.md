# 运行与停止

## 日常启动方式

普通用户只保留两种启动方式。

### 方式一：让 Codex 启动

在 Codex 中选择 `xxsj-fs-ob`，然后发送：

```text
请使用 xxsj-fs-ob 检查 Worker 状态。
如果环境正常且 Worker 尚未运行，请启动 Worker。
不要修改代码和配置。完成后告诉我 PID、日志路径和停止方式。
```

Worker 启动后，不需要保持 Codex 会话开启。

### 方式二：双击 CMD 或快捷方式

双击 Skill 根目录中的：

`start-xxsj-fs-ob-worker.cmd`

或双击指向该文件的 Windows 快捷方式。

调用链：

```text
快捷方式
→ start-xxsj-fs-ob-worker.cmd
→ start-xxsj-fs-ob-worker.ps1
→ scripts\start-worker.ps1
→ Worker
```

`.ps1` 是底层技术脚本，不作为第三种普通用户启动方式宣传。

## 停止 Worker

```powershell
.\scripts\stop-worker.ps1
```

停止脚本读取 `worker.lock` 中的 PID，确认它对应本项目的
`run-auto-worker.ts` 进程，先写入停止请求并等待退出；超时后只终止该 PID。
进程退出后会清理 lock 和停止请求文件，不会结束其他 Node/Python 进程。

## 单次处理

处理一轮可领取任务：

```powershell
.\scripts\run-once.ps1
```

指定飞书 Base 的真实 Record ID：

```powershell
.\scripts\run-once.ps1 -RecordIds "recxxxxxxxx"
```

Record ID 不是平台去重 ID。

不传 `RecordIds` 时，`run-once.ps1` 从 Base 领取当前可处理任务，完成一轮后退出。
传入 `RecordIds` 时，只处理指定记录并退出。

## 受控 Worker

`start-worker.ps1` 不传 `RecordIds` 时启动长期 Worker，持续轮询 Base；普通用户应通过
CMD/快捷方式或 Codex 启动。指定记录是高级的一次性模式：

```powershell
.\scripts\start-worker.ps1 -RecordIds "recxxxxxxxx"
```

具体参数以当前脚本帮助为准。

## 正式运行根

Codex Skill 目录只保存 Skill 描述和启动 wrapper。完整源码、依赖、日志和 Worker 状态位于
实际项目运行根。顶层 PowerShell 启动器按以下顺序解析运行根：

1. `-ProjectRoot`
2. `XXSJ_FS_OB_PROJECT_ROOT`
3. 启动器所在目录（仅当它本身是完整项目根）

无法找到包含 `package.json`、`src` 和 `scripts\start-worker.ps1` 的完整运行根时会立即失败，
不会猜测用户名、盘符或旧 H 盘路径。

## 启动前检查

```powershell
.\scripts\validate-skill.ps1
.\scripts\doctor.ps1
```

## 注意

- 当前正式版本只支持抖音；
- Worker 未运行时，任务会停留在 pending；
- 电脑关机后需要重新启动 Worker；
- 不要同时启动多个 Worker；
- 不要把 B站等未支持任务标记为 done。
